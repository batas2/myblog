Somewhere around the third version of the target-architecture diagram, I started laughing.

Boxes with narrow responsibilities. A coordinator on top. Formal handoffs. Escalation paths for the cases nobody can handle.

I had seen this diagram before. In every HR tool I have ever been onboarded into.

I was not designing a system. I was designing an organization.

The primitives are identical because the problem is identical: coordinating limited intelligences with partial context toward a shared goal. For people the limit is attention and working memory. For agents it is the context window. Same constraint, different units.

So the failure modes transfer as well, and they arrive in the order you would expect.

The bottleneck. Route every interaction through one supervisor and you have serialised your parallelism. One overloaded node, everybody else idle. Any resemblance to a manager whose calendar is the company's critical path is fully intended.

The telephone game. Each relay compresses. The specialist's rich answer becomes the supervisor's summary, which becomes a summary of a summary. In orgs we call that communication overhead. In agents we call it context loss. It is the same tax.

Empire building. Give a supervisor loose instructions and it starts doing the work instead of routing it, badly, because delegating feels riskier than acting. I have met this middle manager. Several times. Some of them were prompts.

The fixes are org-design fixes, translated. Push decisions down to the specialists. Allow direct channels between agents that collaborate often, so not everything has to go up. Define escalation criteria instead of escalation habits.

Then there is the part I cannot put down.

When you design coordination from scratch, with no politics and no history to respect, you would never include a layer whose only function is summarising upward. You would never route every handoff through one node. You would never let two roles both vaguely own the same outcome.

Then you look at your real org chart.

Multi-agent design is org design with a compiler. For the first time our coordination theories produce stack traces instead of opinions.

If you are building one of these right now: which of the three showed up first for you, the bottleneck, the telephone game, or the empire builder? Those are the only ones I have had to design around so far.
